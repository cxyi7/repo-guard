# 暂存隔离与跨进程重入保护

[返回使用说明](../usage-guide.md) · [功能索引](README.md)

保护“只提交选中改动”的工作方式，防止两个提交进程同时修改索引或交叉恢复备份。

## 正常使用

使用 `git add` 或交互式暂存选择需要提交的内容，再提交。暂存隔离属于 pre-commit 的固定基础设施，没有独立功能开关。

| 机制 | 作用 |
|---|---|
| `lint-staged` 暂存快照 | 将格式修复限定在暂存内容，保留部分暂存及未暂存改动 |
| 生命周期互斥锁 | 在操作索引、工作区或备份之前阻止同仓库重叠执行 |
| PID 与随机所有权令牌 | 区分持锁进程，避免清理旧锁时误删新锁 |
| 唯一路径释放 | 正常退出只释放自身锁；异常残留按失效状态处理 |

文件头与函数文档同步也在受保护的暂存处理内完成。保护文件检查读取最终暂存事实，不因前置格式工具修改而使用过期内容。

## 遇到阻断怎么办

`pre-commit/already-running` 表示已有生命周期正在运行：等待它结束后重试，不要启动多个提交窗口争抢索引，也不要手工删除活动锁。

如果格式工具失败，先阅读错误并检查 `git status`、暂存差异和未暂存差异；异常恢复应基于现存变更与备份处理，避免重置工作区。修复工具配置后重新提交，确认只包含原计划提交的内容。

该锁保护 repo-guard 的生命周期；其他人为或第三方进程仍可能修改仓库，因此运行期间应避免同时执行修改索引的独立操作。
