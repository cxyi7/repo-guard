| 问题与复现 | 修复与验证 |

| 正式依赖命令的违规被初始化阶段改成配置错误 | Doctor 单独执行安装前诊断，正式门禁保留统一违规退出码 2 |

| 配置子进程返回后提前退出，被父进程误报清理失败 | 保持 IPC 存活直到统一进程树清理；真实 Prettier 有效、损坏、缺失插件配置均验证 |
| pnpm 6 带 peer 上下文的普通包记录漏查 | 同时匹配带斜杠和 peer 后缀的记录；补充反例测试 |
| 工具满足预设范围但不满足项目精确声明仍可通过 | 同时核对项目声明与能力范围 |
| 构建关闭后残留分析配置仍要求工具 | 只有构建及其分析开关同时开启才登记需求 |
| 多应用根管理入口默认使用 npm；自定义锁路径可能与真实安装不符 | 根入口使用原生明确声明；托管 CI 拒绝自定义锁路径，明确交由项目维护安装流程 |
| 新配置组显式 null 与 Schema 不一致；暂存路径可能被解释为 pathspec | 拒绝 null；索引读取使用字面路径，Git 读取失败不伪装为文件缺失 |

## 证明边界

静态检查只核对明确支持的普通直接依赖及对应锁记录，不证明整个传递依赖树、下载完整性或业务行为。工具配置加载不替代实际 lint、测试和构建。共享根元数据需通过 sharedPaths 明确调度应用。托管质量 CI 不连带启用部署。未知锁格式明确报错。
