# UI Token 指定值与产物校验审查记录

## 本轮范围

在既有 Stylelint 统一配置基础上增加可选的 `uiTokens.values` 和 `uiTokens.artifacts`。指定值保存在 `repo-guard.config.json`，清单继续使用当前 v2 格式。默认不开启未经团队确认的设计值；支持单独检查源码。没有新增 Skill，仅更新接入待办。

源码规则核对直接变量定义、选择器、外层条件及指定值；生成 CSS 通过明确输出映射检查。不会识别图标业务身份，不判断数值设计是否合理，不声称浏览器最终计算值正确。编译表达式需要单独明确输出值，不推断 Sass/Less 计算。

| 新代码使用普通 Error，违反统一错误边界 | 首轮全量回归的架构用例明确失败。改用公共 `configurationError`，未增加白名单；含架构边界的针对性复核 38 项通过。 |
| 上轮移除图标类别后，清单测试仍断言 12 类 | 首轮全量回归显示实际 11、预期 12。改为明确断言 11 类并断言不存在 `icon-size`，未改变清单行为。 |
| 变量名转义可能绕过指定位置匹配 | 审查补充变量名转义解码，回归包含 `--\63` 和普通定义并存，未登记覆盖仍产生违规。 |

| 新配置错误说明未通过中文检查 | 将说明性字段英文改为中文说明，保留稳定配置标识；未扩充语言基线。 |

| 打包预检无法写入系统 npm 缓存 | 首次 dry-run 报 EPERM；将本次打包缓存明确放到工作区 `test/.tmp/npm-pack-cache` 后完成 dry-run，不影响用户系统缓存配置。 |

## 消费项目无规范前提下的复审

用户澄清的原则已写入[消费项目预设设计原则](../features/consumer-preset-design-principles.md)，并链接到 README、功能索引和 Skill 待办。该原则针对未来消费项目，不改变 repo-guard 自身开发规范。本次继续在原功能分支修复，不丢弃已有暂存或未暂存修改。

复审覆盖配置关联、AST 比较、实际样式提取、构建前后检查、证据指纹，以及 Hook、CI、Lighthouse 与受保护构建的配置传递。发现并处理：

| 发现 | 复现及修复 |
| --- | --- |
| 任意函数中的哈希标识仍可能被当成颜色 | `u\72l(#fff)` 与 `u\72l(#ffffff)` 在修复前得到相同键；补测 `element`、`paint`。函数参数不再推断颜色，顶层明确的十六进制值仍支持短写比较。 |
| 选择器注释导致相同位置被判为缺失或未授权 | `.card/*说明*/.active` 与 `.card.active` 的反例先失败；AST 比较去除注释节点，保留后代、组合符和大小写标记。真实来源文件包含选择器注释也能正常检查。 |
| 大写普通 CSS 属性可隐藏重复声明中的错值 | `PADDING:99px; padding:16px` 的反例先未产生违规；改为普通属性名忽略大小写，自定义属性保持大小写敏感。真实构建的 `COLOR:#000;color:#fff` 阻断，只有正确声明时通过。 |
| 输出配置冲突未按属性大小写统一判断 | 同一选择器配置 `color` 与 `COLOR` 的不同值，修复前未拒绝；配置关联校验与执行比较复用同一属性规范化函数。 |
| 同名容器规则可能被当作输出属性事实 | 补测 `container` 声明与容器条件并存；产物值比较只接受声明和变量定义，不接受响应式规则事实。 |

比较规则初次复现：6 项中 3 项失败；输出绑定另有 1 项预期异常缺失。修复后的源码、配置、比较和真实构建组合为 36 项全部通过，日志 `test/.tmp/token-values-followup-real.log`。

本轮跨入口回归：163 项全部通过、0 跳过、0 失败，包含 Token、配置、Hook、CI、构建、Lighthouse、架构边界和文档，日志 `test/.tmp/token-values-followup-regression.log`。`npm run check` 与 `git diff --check` 通过。本轮未重复完整仓库测试；上文 1378 项为上一轮全量结果，不作为本轮新增修复的全量证明。本轮未新增配置字段或依赖，Schema 同步补充属性大小写语义说明。
