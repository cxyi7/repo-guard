# 前端无效代码预设 7.1.0 审查记录

本轮为前端新增默认开启的 Knip 预设和内联配置接入，未实现自动接入 Skill。默认仅检查 files、dependencies、unlisted、exports；TypeScript 预设另外检查 types。既有项目读取配置不会自动改变开关。

## 已复现并修复的边界

- 显式入口写成不存在的文件时，Knip 仍可能处理配置文件并产生非零计数。不能以此证明业务扫描成功。现在对显式 entry/project 路径和空数组进行验证，匹配不到实际文件时阻断；计数本身只作诊断。
- 原生 API 会拆分自定义编译器。合并后恢复公开 compilers 结构，再交由消费项目 Knip 加载。通过自定义扩展名源码的真实未使用导出证明编译器实际执行。
- 无法解析的普通源码路径不应被当成特殊依赖引用跳过。现在只根据问题所属应用的依赖声明过滤；普通相对导入与同名普通工作区依赖保持检查。
- 子进程异常退出保留明确标记的第三方原始诊断；原生配置无限等待使用真实定时器复现，按超时终止，不改写原生配置。

## 配置和使用边界

JSON 内联值按字段合并，原生配置优先，数组整体替换。真实测试覆盖 JSON、JSONC、JS、TS、package.json、指定 CJS 路径、相对导入、自定义编译器和工作区配置。重复开启保留用户范围、忽略项和布尔值；关闭仅改变开关，不删除配置。

入口公开导出默认不按项目内未使用处理，用户可以显式开启 includeEntryExports。动态加载、自动导入以及外部调用不能靠名称猜测；仍需根据真实工程配置补齐入口和插件。通过结果只对应配置的静态分析范围，不自动删除代码或扩充基线。
