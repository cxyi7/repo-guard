# 目录职责与检查联动审查 7.2.0

本次新增应用级目录职责登记与显式路径绑定，覆盖 Java、Node 后端和前端。用途是约定文件应放在哪里，不根据目录名或类名证明业务语义，也不移动目录或自动改写原生工具文件。

## 实现

- entries 登记稳定职责、可编辑路径与用途，允许职责引用；拒绝未知引用、循环、越界、通配符路径和危险键。
- bindings 只允许 Schema 登记的路径字段。普通路径、glob 与正则分别解析，正则转义目录字面值。
- 省略字段采用绑定，用户显式路径优先。等于当前默认值的显式路径同样保留为独立设置；运行配置的覆盖来源只在内存维护，不增加配置或报告字段。
- 写回省略派生字段，Schema 必填字段保留引用模板。初始化使用序列化模板，重复启用不会恢复旧目录，也不会误报无实际变化的开关为已修改。
- 多应用独立解析；仓库公共配置不能代替应用登记目录。暂存快照读取已暂存配置，不借用工作树的未暂存改名。
- AI 规范呈现实际目录与用途，明确职责说明不等于业务语义验证。
