# 前端配置与 Node 后端适用性审查 7.1.3

审查范围为当前前端 22 项应用配置及 Node JavaScript/TypeScript 身份的默认值、启停、原生工具合并、工具就绪、执行入口和共享依赖边界。本轮不新增后端业务预设，不做部署或真实业务接口测试。

## 真实复现并修复

| 问题 | 复现 | 修复 |
|---|---|---|
| 非内联 ESLint 预设缺少工具要求 | Node 默认 preset=true，但需求清单仅返回 eslint/prettier，漏掉实际加载的 @eslint/js 和 TS 插件 | options 与 preset 两种执行路径分别列出真实要求，按身份隔离 Vue |
| 后端普通 Stylelint 初始化误开前端治理 | createStarterConfig 为后端传 stylelintEnabled=true 触发“仅适用于前端”配置错误 | governance 只按前端身份启用 |
| mts/cts 配置加载漏选 | 真实 Node 模块作为唯一加载目标时无法确认配置就绪 | 工具 worker 覆盖 mts/cts，与后端文件模式一致 |
| Windows 短路径误判 | 系统临时目录 ADMINI~1 与 Git 返回的 Administrator 被误判为不同仓库范围 | 入口使用 native realpath 统一真实路径，保留越界与符号链接校验 |
| 单元测试脚本遗漏就绪检查 | 已安装 Vitest、开启 unitTest，但指定脚本不存在仍返回就绪 | checkRequiredScripts 增加 unitTest 精确脚本检查 |
| Prettier 配置加载目标被硬编码扩展名过滤 | 项目明确配置 YAML 目标，真实配置加载仍报没有目标 | 按项目 pattern 选择配置加载目标，不额外限制扩展名；配置加载不代表所有目标均可成功格式化 |

## 前端配置复核矩阵

| 配置领域 | 复核项及实际边界 |
|---|---|
| ESLint、Prettier、Stylelint、typeCheck | 默认开关、原生覆盖、索引隔离、真实违规与修复；TS 新预设开启类型检查，JS 不自动开启 |
| 命名、归位、规模、文件头、函数文档 | 主开关、默认范围、用户覆盖及现有政策测试；目录匹配规则需接入时适配，不能自动识别业务职责 |
| 架构、异步清理、Knip、源码安全 | 规则适用身份、配置边界、受支持语法及反例；静态检查不证明动态使用或所有业务安全 |
| 单元测试、覆盖率、变异测试 | 公共方法范围和映射、工具要求、脚本、报告与现有回归；项目参数与断言仍需合同或接入补齐 |
| build、Lighthouse | 构建选项、预算、包体积、页面前置和执行边界；本轮不以外部业务站点重新采集 Lighthouse |
| 图片及无效图片 | 默认主开关、allFiles、报告动作、动态保留声明及现有回归；报告不等于阻断 |
| 依赖策略、代码位置 | 多包管理器和工具就绪、身份隔离；代码位置保持默认关闭 |

Token 主开关默认开启，但清单和定义属于接入前置；指定值与产物子能力仍按显式配置执行。已有用户值继续优先，不通过降低阈值或增加排除项完成本轮修复。

## Node 实际验证

独立系统临时仓库，仅链接各测试明确使用的真实工具，没有 Vue 安装。自定义 server 目录覆盖 Node JS/TS ESLint、Prettier、tsc、构建后执行 JS、Vitest、dependency-cruiser 和 Knip。全部包含具体失败及修复后的通过验证。mts/cts 工具配置加载和缺失脚本同样真实执行。

Node 源码安全默认只开启动态代码分类；Lighthouse、Vue 清理、UI Tokens 和样式治理不会进入后端默认检查。后端原生配置与脚本必须提供，不能将“支持 Node”表述为免配置支持任何后端框架。
