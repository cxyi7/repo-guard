# 合同执行规则

## 开发前

核对 `workingBranch`、`targetBranch`、`baselineCommit`、Worktree 策略、并行合同重叠和全部未完成义务。

## 开发中

- 代码变化必须能追溯到一个任务和至少一条需求事实。
- 证据使用稳定 `EVD-*` 引用，不使用任意说明文字代替。
- 普通中间失败保留在运行日志；推翻已完成状态或揭示合同遗漏时建立正式 FND。
- 多分支修改同一文件时，记录协调策略、前置落地提交和受影响合同回归覆盖。

## 停止条件

功能归属不清、合同定义需要变化、路径范围需要扩大、并行策略冲突或人工确认缺失时停止写代码并请求确认。
